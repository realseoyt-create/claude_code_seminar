# 서버 운영 가이드

> 이 가이드는 리눅스 서버에서 Java/Python 애플리케이션을 운영하는 담당자를 위한 문서입니다.
> 서버 지식이 전혀 없는 분도 단계별로 따라할 수 있도록 작성했습니다.

---

## 이 가이드가 필요한 상황

- 내가 담당한 앱이 서버에 잘 올라가 있는지 확인하고 싶을 때
- 크론탭에 내 앱이 등록되어 있는지 확인하고 싶을 때
- RV(TIBCO Rendezvous) 통신 설정이 올바른지 확인하고 싶을 때
- 페일오버 테스트 시 무엇을 어떻게 확인해야 하는지 모를 때
- 앱을 어떻게 띄워야 할지 판단하고 싶을 때

---

## 전제조건 — 시작 전 확인사항

### 1. SSH 접속이 가능해야 합니다

SSH는 원격 서버에 접속하는 방법입니다. 터미널(Terminal)에서 아래와 같이 입력합니다.

```bash
ssh 사용자명@서버IP주소
# 예시: ssh appuser@192.168.1.100
```

비밀번호를 묻는 경우 입력하거나, 사전에 받은 SSH 키 파일을 사용합니다.

```bash
ssh -i ~/.ssh/my_key.pem 사용자명@서버IP주소
```

### 2. 필요한 권한이 있어야 합니다

- 일반 명령어: 본인 계정으로 충분합니다.
- 다른 사용자의 크론탭 확인: `sudo` 권한이 필요합니다.
- 시스템 서비스 확인: `sudo` 권한이 필요합니다.

권한이 없는 경우 인프라/서버 담당자에게 요청하세요.

## 핵심 용어 설명

### 프로세스 (Process)
서버에서 실행 중인 프로그램 하나하나를 **프로세스**라고 합니다. Java 앱을 실행하면 하나의 프로세스가 생기고, 서버에서 `ps` 명령어로 확인할 수 있습니다.

### 데몬 (Daemon)
백그라운드에서 사용자 개입 없이 자동으로 실행되는 프로세스입니다. RV 데몬(rvd)처럼 서버가 시작될 때 함께 시작되어 항상 실행 중인 프로세스입니다.

### 크론 / 크론탭 (Cron / Crontab)
리눅스의 **자동 스케줄러**입니다. "매일 오전 9시에 이 스크립트를 실행해라"와 같은 명령을 등록해두면 자동으로 실행합니다. 크론탭(crontab)은 그 스케줄 목록입니다.

### TIBCO RV (Rendezvous)
시스템 간 **메시지를 주고받는 미들웨어**입니다. 예를 들어, 주문 시스템이 결제 시스템에게 "주문이 들어왔어"라고 알려줄 때 RV를 통해 메시지를 전달합니다. RV 데몬(rvd)이 메신저 역할을 합니다.

### 페일오버 (Failover)
**주 서버(Active)가 장애**가 났을 때, **대기 서버(Standby)가 자동으로 역할을 이어받는 것**입니다. 서비스가 중단 없이 계속 운영되도록 하는 고가용성(HA) 구성입니다.

### Active / Standby 서버
- **Active 서버**: 현재 실제로 서비스를 처리하는 서버
- **Standby 서버**: 평소에는 대기 중이다가 Active가 장애 시 역할을 이어받는 서버
